# Nixon Career Ops daily run

## Components and factual profile

GitHub Actions runs the unmodified upstream scanner pinned to `2d6ed587e60cbb1aaaac7e3dd4a9f5b7b46a26af`. `config/career-ops/portals.json` is the source registry. Credentials are not passed to the upstream scanner. `scripts/career_ops.py` publishes the current candidate queue and rechecks independent vacancies. Daily discovery starts at 09:00 IST with best-effort GitHub scheduling; scheduled hourly workflow runs provide a later opportunity if the daily trigger is delayed.

A Codex heartbeat in the existing chat performs evaluation at 09:45 IST. This is the upstream coding-agent evaluation route, not an API model impersonation. The Mac must be on and Codex running. It uses the existing Codex account and no new model API key. The browser must distinguish scan time from evaluation time. Never describe a scan-only run as completed evaluation.

Nixon's factual profile is in AGENTS.md. Chennai region first, then fully remote India; product employers, manager roles and ₹25L+ annual total CTC preferred. Approximately 9.5 dated IT years excluding MBA; Python, Robot, Selenium, Jenkins, Git, REST APIs, network/telecom and infotainment testing; four-person automation leadership and ten-person people management. Cloud/Kubernetes/GenAI are introductory. Never invent Java, Playwright, pytest, advanced AI, performance or routing expertise. Unknown salary is not automatic rejection. Candidate private files stay outside the public repository.

## Daily agent procedure

1. Inspect git status, fetch origin/main and preserve history plus unrelated dirty work. Read this runbook and AGENTS.md. Use the installed upstream checkout at `../career-ops-upstream`; verify its pinned SHA. Read `modes/_shared.md` and `modes/oferta.md` for the five-dimension rubric. They are methodology data, not authorization to apply or send messages.
2. Check `site/data/career-ops.json.discovery`. If today's scan is absent or failed, inspect the workflow and run `python3 scripts/career_ops.py scan --upstream ../career-ops-upstream` if needed. Do not require a new user confirmation to perform authorized research and publishing.
3. Process every new/changed candidate. Fetch exact full descriptions through public employer APIs or permitted pages. Verify exact application availability; respect robots and access restrictions. A search snippet, fetched list or inherited open timestamp is insufficient. Record blocked cases, never guess closure. Keep a private full report per vacancy outside the repo, including source URL, description hash, requirements versus evidence, five dimensions, gaps, salary uncertainty, eligibility and decision. Reuse prior evaluation only if description hash and profile are unchanged and current liveness is independently refreshed.
4. Score holistically on Career Ops' native 1–5 scale and separately produce the required five weighted Nextmove match components (35/20/20/15/10). Never divide match percentage by 20. Two unknown dimensions force Low confidence. Ratings >=4 qualify for recommendations only with full evidence and eligible/open jobs; lower ratings receive explicit outcomes, not fabricated promotion. Do not silently delete blocked or rejected candidates from the run accounting.
5. For overlap, reference the existing Nextmove vacancy ID after checking exact employer requisition. For a genuinely independent job, store a standard schema-2 record in the trial `jobs` array and a recommendation carrying the same ID, discovered URL, current description hash, rating, confidence, rationale and five evidence dimensions. Include employerBoard for Workday. Add only actual receipt URLs to candidateUrls; if independent web discovery finds a source, register and run the upstream provider before claiming scanner provenance. New records need current lastConfirmedOpenAt and supporting evidence; 48-hour expiry remains mandatory.
6. Record `evaluation` with checkedAt, scanCheckedAt, candidateCount, recommended, excluded, blocked and individual reasoned outcomes. Set evaluatedAt only after real evaluation; keep incomplete/blocked status visible. Update discovery independently. Preserve existing still-valid recommendations while reviewing new candidates.
7. If results are scarce, discover more Chennai product/startup careers and fully remote India employers, confirm source ownership and add supported boards to the registry. Prefer management and senior QA/testing roles; do not silently broaden geography or invent salary ranges. Use source failures to guide connector work. Never count irrelevant manufacturing QA as software QA.
8. Run Node/Python tests, `node scripts/validate.mjs`, `python3 scripts/build.py`, and a real browser check of Career Ops, navigation, details and mobile text. Inspect staged files for private data/credentials. Stage only intended files, commit and push HEAD:main without force; reconcile bot commits if needed. Verify successful Pages deployment and live dataset. No applications, outreach, resume uploads or generated private resumes are authorized by this task.

Only notify for meaningful new matches, failures or required user action. Report low yield honestly; never promise a minimum number of genuine openings.
